# Landed is not live

A change to musterd.io can be merged, accepted and recorded `done` while the public site keeps serving the copy it removed, because the deploy is a separate manual act (ADR 308) that no acceptance reaches; since 2026-09-24 the site carries its build stamp and the live build-publisher reports the gap to the deploy-authorized seat without anyone looking.

## The measured instance (2026-09-19, lane 01M2XD2RPG)

Measured by miley ~10:45 against the live site, with `main` at `d2870ec0`. The deployed homepage still carried three strings that #1561 removed, and lacked the one it added (2026-09-19; falsify: `git show 7ae57d44 -- packages/web` lists exactly these four): <!-- claim: other -->

| string | on main after #1561 | on musterd.io 2026-09-19 |
| --- | --- | --- |
| `ss__facade-badge` (the all-caps LIVE pill over a dark channel) | removed | present |
| `live broadcast` (the facade's state label) | removed | present |
| `Who did what is never a question` / `nothing on the roster is anonymous` | scoped out | present |
| `musterd on Twitch` (the honest label put in the badge's place) | added | absent |

The deploy boundary, measured rather than assumed: #1567 (`c432fbb3`) was live, #1561 (`7ae57d44`) and #1570 (`3076e7a0`) were not. musterd.io sat at `c432fbb3` with `main` two site-affecting commits past it.

What made it worse than a stale deploy: #1561 landed at 08:25, big-body accepted it at 10:23 with "the dark-channel facade no longer asserts a false live state" — true of `main`, false of the site — and the lane read `done`. Three careful seats and a human all believed it was fixed. Acceptance (ADR 192) judges the *landed* outcome; for a web surface, landed means merged, and nothing asked whether it reached production.

By 2026-09-24 13:xx the site had been deployed and matched `main` exactly (asset hashes `index-D-SIKMmf.js` / `routes-VCFIYywj.js` on both; visible-text diff of `/` and `/watch` empty). Nothing recorded when that deploy happened — ADR 308 §Observability had already named "a deploy is invisible to the coordination record" as the gap.

## The instrument (2026-09-24)

Three pieces, each useless alone:

1. **The origin says which commit it serves.** `pnpm --filter @musterd/web build` stamps `dist/build.json` (ADR 135); `stage:site` copies it into the deploy as `/build.json` and refuses a build with no commit ref (ADR 302 amendment 2026-09-24). Until the first deploy after this landed, `/build.json` is a 404 and the check reports `no_marker` — it cannot measure a deploy that predates it, and says so rather than guessing (2026-09-24; falsify: `curl -s https://musterd.io/build.json` — a 404 after miley's next deploy means the stamp did not ship). <!-- claim: other -->
2. **The comparison.** `musterd service site-gap` fetches the marker, resolves it in the local checkout, and lists `git log <deployed>..origin/main -- packages/web`. Exit 1 when behind, so it is a gate a script can ask. `packages/web` is the whole public artifact and also holds the daemon-only routes, so a `/live`-only commit counts as "site changed" — a false *behind* costs one glance at the list; a false *current* is the defect above.
3. **The reporter.** The live build-publisher (`~/.musterd/live/build.sh`, regenerated by `musterd service install --live`) runs `site-gap --raise` on **every** poll, before its "already current" early exit — a deploy moves the site without moving `main`, so the check cannot hang off the build. It speaks as the `live` service seat (ADR 232 lets a ledger seat send `ask`): one advisory `ask` to miley (the seat ADR 308 names) per deployed ref, and a `resolve` on that thread when the site catches up. `main` moving again while the site is still behind does not re-raise. State: `~/.musterd/live/site-gap.json`.

The publisher's tail is `|| true` and guarded by `command -v musterd`: the instrument can never fail the publish.

## What it does not do

- It does not deploy. ADR 308 stands: the act is miley's, and the point of the ask is that the wait becomes a fact in the stream rather than a thing a seat notices.
- It does not reach the acceptor. The lane's third option — the acceptance ask carrying "this surface is public and is/is not live" — was not built; the acceptor still judges the landed outcome.
- A publisher host with no `musterd` on PATH, or with the live seat unprovisioned, prints the gap line to `build.log` and sends nothing (2026-09-24; falsify: run `MUSTERD_SERVICE_TOKEN_FILE=/nonexistent musterd service site-gap --raise` against a behind origin and see "would raise but the live service seat is unprovisioned") — the ADR 232 posture: degrade to silence, never fail the tick. <!-- claim: other -->
