# Follow-up notes — one conversation, one page

_The form nick fills in after a conversation, so a next step can be dated while the detail is still
in his head. Internal; nothing here travels. It exists because [traction-plan](../../design/traction-plan.md)
§8 asks for three or more threads with a next step dated in Q1, and a thread without a date is a
business card._

Copy this file per conversation into `docs/design/follow-ups/<YYYY-MM-DD>-<company>.md`, or keep it
on paper and type it up the same evening. **The same evening** is the only rule that matters — a
note written three days later records what you wish had been said.

## What they run today

The point of this block is to find out whether they have the problem, before deciding whether we
have the answer. Their words, not ours.

| field | value |
| --- | --- |
| how many agents, on what harness | |
| do two ever touch the same repo | |
| what happens today when they collide | |
| who is accountable when one ships something wrong | |
| the thing they complained about unprompted | |

**Do they have the problem?** yes / no / not yet — and one sentence on why you think so.

If the answer is no, write it down as a no. A list of maybes is worth less than a short list of
yeses, and the no is the more useful record: it tells us who the product is not for, which is the
same information the scope decision is built on.

## What this conversation changed

they assumed we had. This is the field that makes the form worth filling in twice.
