> musterd lane (subagent-driven execution is disabled here). Steps use checkbox (`- [ ]`) syntax

**Goal:** Make the shipped ADR 227 role layer honest (help/CLI shows both worlds) and measurable
(role-filtered discovery leaves an audit trail; the inc-2 eval is actually run), then amend the ADR
to match reality.

**Architecture:** The role filter moves from the MCP client into the daemon (`GET /members?role=`),
which writes a `roster.role_query` audit row — the `infra.touch.warned` pattern. The CLI `role`
command renders the team library (from the same roster GET) above the ADR 029 provisioning
templates. The ADR amendment rewrites the eval around the new audit signal and records the first
warn→redirect measurement.

**Tech Stack:** TypeScript monorepo (pnpm), vitest, better-sqlite3, zod. Spec:
`docs/superpowers/specs/2026-08-06-adr-227-closeout-design.md`.

- [ ] **Step 1: Run the warn→redirect eval against the live DB (read-only)**

```bash
sqlite3 -header ~/.musterd/musterd.db "
SELECT datetime(a.ts/1000,'unixepoch') AS warned_at, a.actor,
       json_extract(a.detail,'\$.verb') AS verb,
       json_extract(a.detail,'\$.holders') AS holders,
       (SELECT GROUP_CONCAT(mm.act || '→' || COALESCE(tm.name,'team'))
          FROM messages mm
          JOIN members fm ON fm.id = mm.from_member
          LEFT JOIN members tm ON tm.id = mm.to_member
         WHERE fm.name = a.actor
           AND mm.ts BETWEEN a.ts AND a.ts + 30*60*1000
       ) AS sends_within_30m
  FROM audit a
 WHERE a.action = 'infra.touch.warned'
 ORDER BY a.ts;"
```

For each of the 3 warns, classify by hand from the output (and `body` text if needed —
`SELECT act, body FROM messages …` scoped the same way): **redirected** (a following ask/message
directed at a platform holder — izzo or autorefresh), **deliberate proceed** (the seat was doing
sanctioned platform work), or **neither**. Compute warn→redirect rate = redirected / total.
