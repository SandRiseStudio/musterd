# Federation 3b-i — sync wire format and push: implementation plan

> **For agentic workers:** executed **inline, by the seat that owns the lane** (musterd ADR 150 lane
> ownership). Do NOT dispatch writing subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an enrolled machine push its own origin-stamped messages to the hub, which stores them
in an append-only staging log under a canonical total order — without anything being applied to
`messages` yet.

**Architecture:** Pushed events land in `sync_log`, never in `messages`. A store module owns every
guarded write; the route is thin and authenticated by `msnode_`; a 60s loop shaped like
`seeds/ingest.ts` drives the push from the daemon side.

**Tech Stack:** TypeScript (ESM, `.js` specifiers), better-sqlite3 (synchronous, single writer), zod,
vitest, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-08-28-sync-push-design.md`

**Lane:** `01M12FKECH1CA0DCY7X3H0KMBE` · **Branch:** `stanley/federation-sync-push` · base `3b8415cf`

## Global Constraints

- **ADRs governing:** 325 (topology and the sync model), 328 (the credential admitting the surface),
  331 (the ordering substrate). Contradicting any means stopping to write an ADR.
- **Nothing in this slice writes to `messages` or touches `nodes.next_seq`.** Task 2's test pins it;
  if a later task needs to break it, the slice boundary was wrong — stop and say so.
- **A node may push only its own events** — every batch is checked against the authenticated node.
- **Migrations are rewind-and-replay safe** — `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT
  EXISTS`. The migration tests rewind `schema_version` and replay the tail.
- **`db.transaction` COMMITS on a returned value.** Only a throw rolls back — the 3a bug. Any
  refusal inside a transaction throws.
- **Gates before submit, the WHOLE chain:** `pnpm install && pnpm -r build`, then `pnpm typecheck`
  (check the **exit code**, not the tail — a passing `dist:check` masked a real `tsc` failure for
  three tasks in 3a), `pnpm lint`, `pnpm format:check` (fourteen checks, including
  `arch-trees:check`, which CI caught in 3a because I never ran it), and the three suites.
- **New source files need architecture-tree entries** in `docs/architecture/03-server.md` —
  `arch-trees:check` fails otherwise.

```ts
// packages/protocol/src/sync.ts
import { z } from 'zod';
import { EnvelopeSchema } from './envelope.js';

/**
 * The daemon↔hub sync surface (ADR 325), increment 3b-i of the federation build.
 *
 * The replicated event is the ENVELOPE plus its origin stamp — not a parallel message shape.
 * `Envelope` already names its sender by seat name and its team by slug, which is exactly what
 * crossing a machine boundary requires: `messages.from_member` is a daemon-private id (ADR 325
 * keeps `id`/`token_hash` private and replicates roster identity via git), so shipping it would
 * dangle on the receiver or, worse, resolve to a different seat holding that id there.
 *
 * Composing `EnvelopeSchema` rather than restating its fields keeps the act vocabulary, the `meta`
 * rules and the slug regex in ONE place. A restatement would drift, and the drift would look like
 * "this act is replicable but unvalidated".
 */

/** One replicated event. */
export const SyncEventSchema = z.object({
  envelope: EnvelopeSchema,
  /** The `nodes` row id that minted this event — a principal the hub authenticated (ADR 328 §1). */
  origin_node: z.string().min(1),
  /**
   * Positive, not merely non-negative: `next_seq` holds the NEXT value to assign and starts at 1
   * (ADR 331 §Decision 2), so seq 0 never exists. Admitting it would invite a reader to treat 0 as
   * "unset" and a gap check to compare against a value no origin ever wrote.
   */
  origin_seq: z.number().int().positive(),
  /**
   * How the sending session was animated (ADR 131 §4). Travels because it is an attested fact about
   * the event — the reason ADRs 101/158 stamp attestation per-event at insert is that it survives
   * replication. `created_at` deliberately does NOT travel: it is local receipt time, and shipping
   * the origin's would assert a falsehood about when this machine learned of the event.
   */
  from_provenance: z.string().nullable(),
});
export type SyncEvent = z.infer<typeof SyncEventSchema>;

/** One push is bounded — an unbounded batch is an unauthenticated-adjacent memory primitive. */
export const SYNC_PUSH_MAX_BATCH = 500;

export const SyncPushRequestSchema = z.object({
  events: z.array(SyncEventSchema).max(SYNC_PUSH_MAX_BATCH),
});
export type SyncPushRequest = z.infer<typeof SyncPushRequestSchema>;

/** `hub_seq_high` lets a pusher see the canonical order advancing without a second round trip. */
export const SyncPushResponseSchema = z.object({
  accepted: z.number().int().nonnegative(),
  hub_seq_high: z.number().int().nonnegative(),
});
export type SyncPushResponse = z.infer<typeof SyncPushResponseSchema>;
```

```ts
import { insertMessage } from '../store/messages.js';
import { createTeam } from '../store/teams.js';

/**
 * The 3b-i containment property, and the reason the slice boundary is real: ADR 331 §Consequences
 * warned that a second insert path skipping `insertMessage` would break gaplessness. This slice
 * answers that by not building one — nothing here writes to `messages` or advances `next_seq`.

 * Written before the ingest exists so it cannot be retrofitted to whatever the code turned out to

    messages: db.prepare('SELECT COUNT(*) AS n FROM messages').get(),
    seqs: db.prepare('SELECT id, next_seq FROM nodes ORDER BY id').all(),
```

```ts
import { describe, expect, it } from 'vitest';
import { openDb } from '../db/open.js';
import { createTeam } from '../store/teams.js';
import { hubHead, ingestBatch, SyncGapError, SyncOriginError } from './log.js';

function seed() {
  const db = openDb(':memory:');
  const team = createTeam(db, { slug: 'revive' });
  for (const id of ['node-a', 'node-b']) {
    db.prepare('INSERT INTO nodes (id, team_id, label, next_seq) VALUES (?, ?, ?, 1)').run(
      id,
      team.id,
      id,
    );
  }
  return { db, team };
}

function ev(node: string, seq: number, id = `${node}-${seq}`) {
  return {
    envelope: {
      id,
      v: 'musterd/0.3' as const,
      team: 'revive',
      from: 'ada',
      to: { kind: 'team' as const },
      act: 'message' as const,
      body: 'hi',
      ts: 1000 + seq,
    },
    origin_node: node,
    origin_seq: seq,
    from_provenance: null,
  };
}

describe('hub ingest (ADR 325)', () => {
  it("refuses a batch carrying another node's origin", () => {
    const { db, team } = seed();
    // ADR 328 §1: an event's origin is a fact the hub authenticated, not a string the sender chose.
    // Without this check that sentence is aspiration — one compromised machine could mint events
    // attributed to any other.
    expect(() => ingestBatch(db, team.id, 'node-a', [ev('node-b', 1)])).toThrow(SyncOriginError);
    expect(db.prepare('SELECT COUNT(*) AS n FROM sync_log').get()).toEqual({ n: 0 });
    db.close();
  });

  it('refuses a gap and names the resume point', () => {
    const { db, team } = seed();
    ingestBatch(db, team.id, 'node-a', [ev('node-a', 1)]);
    try {
      ingestBatch(db, team.id, 'node-a', [ev('node-a', 3)]);
      throw new Error('expected a gap refusal');
    } catch (err) {
      expect(err).toBeInstanceOf(SyncGapError);
      expect((err as SyncGapError).expectedSeq).toBe(2);
    }
    db.close();
  });

  it('is idempotent — a replayed batch inserts nothing and still acks', () => {
    const { db, team } = seed();
    const first = ingestBatch(db, team.id, 'node-a', [ev('node-a', 1), ev('node-a', 2)]);
    expect(first.accepted).toBe(2);
    // A lost ack is the realistic case; the pusher resends the same batch.
    const replay = ingestBatch(db, team.id, 'node-a', [ev('node-a', 1), ev('node-a', 2)]);
    expect(replay.accepted).toBe(0);
    expect(db.prepare('SELECT COUNT(*) AS n FROM sync_log').get()).toEqual({ n: 2 });
    db.close();
  });

  it('keeps two origins independent and hub_seq dense across them', () => {
    const { db, team } = seed();
    ingestBatch(db, team.id, 'node-a', [ev('node-a', 1)]);
    ingestBatch(db, team.id, 'node-b', [ev('node-b', 1), ev('node-b', 2)]);
    ingestBatch(db, team.id, 'node-a', [ev('node-a', 2)]);

    const rows = db
      .prepare<[], { origin_node: string; origin_seq: number; hub_seq: number }>(
        'SELECT origin_node, origin_seq, hub_seq FROM sync_log ORDER BY hub_seq',
      )
      .all();
    expect(rows.map((r) => r.hub_seq)).toEqual([1, 2, 3, 4]);
    expect(rows.map((r) => `${r.origin_node}:${r.origin_seq}`)).toEqual([

      'node-b:1',
      'node-b:2',
      'node-a:2',

    expect(hubHead(db, team.id)).toBe(4);
    db.close();

    expect(() =>

  it('writes nothing to messages and moves no next_seq', () => {
    const { db, team } = seed();

    expect(db.prepare('SELECT COUNT(*) AS n FROM messages').get()).toEqual({ n: 0 });
    expect(
      db.prepare<[], { next_seq: number }>('SELECT next_seq FROM nodes').all(),
    ).toEqual([{ next_seq: 1 }, { next_seq: 1 }]);
    db.close();
  });
});
```

```ts
// packages/server/src/sync/log.ts
import type { SyncEvent } from '@musterd/protocol';
import type { Database } from 'better-sqlite3';

/**
 * The hub's staging log for pushed events (ADR 325 increment 3b-i).
 *
 * Ingest lands events HERE and nowhere else — never in `messages`, never touching
 * `nodes.next_seq`. The fold into `messages` is 3b-ii, one implementation run by hub and puller
 * alike, which is what keeps ADR 331 §Consequences' "second insert path" a single reviewed thing
 * rather than two that drift.
 */

/** A batch arrived out of order. `expectedSeq` is where the pusher should resume. */
export class SyncGapError extends Error {
  constructor(readonly expectedSeq: number) {
    super(`sync gap — expected origin_seq ${expectedSeq}`);
    this.name = 'SyncGapError';
  }
}

/** A batch carried an origin that is not the authenticated node's. */
export class SyncOriginError extends Error {
  constructor() {
    super('a node may push only its own events');
    this.name = 'SyncOriginError';
  }
}

export function highestContiguousSeq(db: Database, nodeId: string): number {
  // The log is gapless per origin by construction — ingest refuses anything else — so MAX is the
  // contiguous head rather than merely the largest value seen.
  const row = db
    .prepare<[string], { high: number | null }>(
      'SELECT MAX(origin_seq) AS high FROM sync_log WHERE origin_node = ?',
    )
    .get(nodeId);
  return row?.high ?? 0;
}

export function hubHead(db: Database, teamId: string): number {
  const row = db
    .prepare<[string], { high: number | null }>(
      'SELECT MAX(hub_seq) AS high FROM sync_log WHERE team_id = ?',
    )
    .get(teamId);
  return row?.high ?? 0;
}

/**
 * Ingest one pushed batch. Throws `SyncOriginError` or `SyncGapError` — both roll the whole batch
 * back, because a partially applied batch leaves a hole the pusher believes it has closed.
 */
export function ingestBatch(
  db: Database,
  teamId: string,
  nodeId: string,
  events: SyncEvent[],
  now: number = Date.now(),
): { accepted: number; hub_seq_high: number } {
  return db.transaction(() => {
    let expected = highestContiguousSeq(db, nodeId) + 1;
    let accepted = 0;

    for (const event of events) {
      if (event.origin_node !== nodeId) throw new SyncOriginError();

      // A replay of something already held is a no-op, not a gap: the pusher resending after a lost
      // ack is the expected case, and it must not look like corruption.
      if (event.origin_seq < expected) continue;
      if (event.origin_seq !== expected) throw new SyncGapError(expected);

      const hubSeq = db
        .prepare<[string], { next_hub_seq: number }>(
          `INSERT INTO sync_meta (team_id, next_hub_seq) VALUES (?, 2)
           ON CONFLICT(team_id) DO UPDATE SET next_hub_seq = next_hub_seq + 1
           RETURNING next_hub_seq - 1 AS next_hub_seq`,
        )
        .get(teamId)!.next_hub_seq;

      const res = db
        .prepare(
          `INSERT INTO sync_log (id, team_id, origin_node, origin_seq, hub_seq, payload, received_at)
           VALUES (?, ?, ?, ?, ?, ?, ?)
           ON CONFLICT(id) DO NOTHING`,
        )
        .run(
          event.envelope.id,
          teamId,
          nodeId,
          event.origin_seq,
          hubSeq,
          JSON.stringify(event),
          now,
        );
      if (res.changes > 0) accepted += 1;
      expected += 1;
    }

    return { accepted, hub_seq_high: hubHead(db, teamId) };
  })();
}
```

Note the upsert's `VALUES (?, 2)` with `RETURNING next_hub_seq - 1`: the first event for a team
allocates `hub_seq` 1 and leaves `next_hub_seq` at 2, matching the "next value to assign" meaning
`nodes.next_seq` established in increment 2. Do not copy the `DEFAULT 1` from the schema into the
insert — that would hand out 1 twice.

- [ ] **Step 3: Implement the route**

```ts
// packages/server/src/transport/http.ts — in the team-scoped block, after the /nodes/* routes
//
// ── The sync surface (ADR 325 increment 3b-i). Authenticated by `msnode_` and by nothing else:
// ADR 328 §3 admits a node here and to no other route, so this is the first and only consumer of
// `authenticateNode`. Pushed events land in `sync_log`; nothing here writes to `messages`.
if (method === 'POST' && rest === '/sync/push') {
  const team = requireTeam(ctx.db, slug);
  const node = authenticateNode(ctx.db, team.id, bearer(req));
  if (!node) {
    throw new MusterdError(
      'unauthorized',
      'the sync surface authenticates with a machine credential (msnode_) for this team',
    );
  }
  const body = parseOrBadRequest(SyncPushRequestSchema, await readJson(req));
  try {
    const result = ingestBatch(ctx.db, team.id, node.id, body.events);
    return sendJson(res, 200, SyncPushResponseSchema.parse(result));
  } catch (err) {
    // Both refusals are conflicts, not faults: the caller can act on either. A 500 here would read
    // as "the hub is broken" for what is actually "resend from seq N".
    if (err instanceof SyncGapError) {
      return sendJson(res, 409, {
        error: { code: 'conflict', message: err.message },
        expected_seq: err.expectedSeq,
      });
    }
    if (err instanceof SyncOriginError) {
      throw new MusterdError('forbidden', err.message);
    }
    throw err;
  }
}
```

The gap response is hand-built rather than thrown as a `MusterdError` because it carries a field the
error envelope has no room for; keep `error: { code, message }` byte-compatible with
`ErrorBodySchema` so the CLI's parser still reads the message (the 3a bug: a flat `{error, message}`
made every refusal render as a bare "server error (409)").

```ts
export const SYNC_PUSH_INTERVAL_MS = 60_000;

/** One team's push pass. Returns how many events the hub accepted. Exported for through-DB tests. */
export async function pushTeam(ctx: Ctx, team: { id: string; slug: string }, now = Date.now()) {
  const enrollment = readNodeState().nodes[team.slug];
  if (!enrollment) return 0; // not enrolled: the single-machine case, and not an error
  // …read local_node, read the cursor, select messages for this origin above it, POST, and advance

}
```
